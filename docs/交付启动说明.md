# 机器人端交付启动说明

普通使用者不需要运行任何 ROS 命令，也不应直接访问机器人电脑。部署人员完成一次性安装后，机器人电脑开机即自动启动底盘、雷达、定位、导航、自动定位恢复和平台网关。

机器人只通过本机 Edge Gateway 主动连接控制站的 MQTT/mTLS 端口。网页、中心 API、数据库和 MQTT Broker 均不运行在机器人电脑；浏览器不能访问 ROS、DDS、串口、CAN 或 `/cmd_vel`。

## 一次性安装

1. 控制站已完成 EMQX mTLS 部署并为本车创建独立的 MQTT 凭据、客户端证书和私钥。
2. 创建私有运行参数文件，绝不把密码或私钥提交回工作空间：

```bash
sudo install -d -o root -g boreas -m 0750 /etc/lr-robot/mqtt
sudo cp src/robot_decision/config/edge_gateway.control-station.yaml.example /etc/lr-robot/edge-gateway.yaml
sudo chown root:boreas /etc/lr-robot/edge-gateway.yaml
sudo chmod 0640 /etc/lr-robot/edge-gateway.yaml
```

编辑 `/etc/lr-robot/edge-gateway.yaml`，填写控制站 DNS/IP、本车 `robot_id` 和 `mqtt_username`、密码、证书路径；`active_map_id`、`allowed_map_ids` 与地图范围必须与本车实际加载的地图一致。

3. 确认工作空间已完成编译，且机器人能正常执行 `full_navigation.launch.py`。
4. 执行：

```bash
cd /home/boreas/Library_robot
chmod +x scripts/start-robot-runtime.sh scripts/install-robot-runtime-autostart.sh
sudo ./scripts/install-robot-runtime-autostart.sh
sudo sh -c 'printf "%s\\n" "LR_GATEWAY_PARAMS_FILE=/etc/lr-robot/edge-gateway.yaml" "LR_ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST" > /etc/lr-robot/runtime.env'
sudo chown root:boreas /etc/lr-robot/runtime.env
sudo chmod 0640 /etc/lr-robot/runtime.env
sudo systemctl restart lr-robot-runtime.service
```

安装前请先停止手工运行的导航或 Gateway 终端，避免重复占用底盘、雷达和 ROS 话题。`ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST` 会限制 ROS 2 发现仅在车载机内；即使控制站或 Wi-Fi 暂时不可用，IMU、AMCL/Nav2 和定位不会因此停止，Gateway 会自动按退避策略重连 MQTT。

## 本地单机调试兼容

不设置 `/etc/lr-robot/runtime.env` 中的 `LR_GATEWAY_PARAMS_FILE` 时，运行时继续读取工作空间 `config/edge_gateway.yaml`，其 `mqtt_host: 127.0.0.1` 适用于同机调试。不要在生产车辆上为了测试而开放 ROS/DDS 或直接向 `/cmd_vel` 发布消息。

## 日常使用

开机后系统会自动处理定位：

1. 同一张地图、机器人未被搬动时，自动恢复上次确认且稳定的 AMCL 位置。
2. 没有可用历史位置时，自动使用激光雷达和地图进行全局位置匹配；此过程不会驱动车辆。
3. 只有定位稳定后，平台才允许创建导航任务。

机器人被搬到其他区域、环境变化太大或自动匹配超过 30 秒仍未收敛时，平台会显示“需要确认位置”。此时才需要操作员在定位界面设置初始位姿；这是避免错误导航的必要安全保护。

### 网页确认当前位置（推荐）

无需在机器人电脑上打开 RViz。管理员在平台的“图书管理 -> 地图建模”选择当前地图后，点击 **网页确认位置**：

1. 选择需要确认的机器人。
2. 在“初始位置”中选择已导入的巡航点、停靠位、充电区或交付点；若没有合适的点，则进入地图选择模式，从机器人实际位置向机器人车头方向拖动。
3. 核对弹窗内的坐标和朝向，点击“确认并发送”。
4. 系统确认 AMCL 已接收该初始位置后，状态会变为“实时定位”并保存为下次启动的恢复位置；此后才可导航。

该操作只向 AMCL 提供初始位置，**不会驱动车辆**。必须由能看到机器人实际位置的管理员操作；地图与机器人当前加载地图不一致时，平台和机器人网关都会拒绝该操作。

请勿通过手推机器人来验证实时位置变化。手推时轮编码器不会产生底盘里程计，AMCL 无法可靠计算移动距离；应让机器人通过自身动力低速行驶，再观察地图坐标变化。若机器人自身行驶时位置仍不变化，应由维护人员检查轮速/编码器和 `/odom`。

### 地图显示“位置过期”或“未定位”

这表示 AMCL 尚未获得可靠的 `map` 坐标。请先等待“恢复上次位置”或“自动搜索位置”完成；无需重启机器人或服务。

1. 在 RViz 中使用 **2D Pose Estimate**，在地图上点击机器人实际位置并拖动确定机器人朝向。
2. 等待约 2 秒，地图建模页面应显示“实时定位”和机器人图标。

仅在已准确确认机器人仍位于指定坐标时，部署人员可在机器人电脑终端执行下面的命令设置初始位姿；位置不确定时不得猜测坐标：

```bash
cd /home/boreas/Library_robot
source /opt/ros/jazzy/setup.bash
source install/setup.bash
ros2 launch robot_decision init_pose.launch.py x:=1.342 y:=-0.146 yaw:=-1.48
```
